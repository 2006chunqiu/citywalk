## 五、这份数据能直接用吗

**可以直接用的字段**：名称、坐标（已转 GCJ-02）、类别、OSM 溯源 ID。

**必须人工补齐的字段**：

| 字段 | 为什么必须人工 | 怎么补 |
|---|---|---|
| `address` | 缺失率高，OSM 不强制填 | 高德逆地理编码按坐标反查 |
| `reason` | OSM 没有“值不值得走一趟”的评价 | 写一句话入选理由 |
| `stay_minutes` | 现在是按类别的默认值 | 按实际参观点位修正 |
| `open_time` | OSM 覆盖不全 | 高德 POI 详情的 `business.opentime` |
| `tag_ids` | OSM 标签是功能分类，不含“文艺”“出片” | 人工判断，或按关键词规则初筛 |
| `verified_*` | 无 | 逐点在高德地图按名称搜索核验 |

## 六、与本项目的适配建议

1. **不要直接用 OSM 标签当兴趣标签**。OSM 的 `tourism=museum` 只说明它是博物馆，不说明它“适合拍照”。兴趣标签必须人工判断后写入 `tag_ids`。
2. **地址一律用高德逆地理补**。OSM 的地址字段在武汉覆盖率很低，而我们的分享页与卡片都要展示地址。
3. **坐标已经是 GCJ-02**，可直接入库；但入库前建议用高德「坐标转换」或 POI 搜索抽样比对 3–5 个点位，确认没有整体偏移。
4. **优先使用“历史建筑”与“公园绿地”两类**。这两类 OSM 覆盖最好、且客观属性强（是不是文保单位、是不是公园），人工判断成本最低。
5. **“美食小吃”“市井烟火”靠 OSM 不可行**。这类点位需要真实的店名与营业状态，OSM 覆盖率低且更新慢，必须用高德 POI 检索 + 人工筛选。

## 七、建议的补全流程

1. 按标签分层抽样，每类先挑 20 个候选（合计约 160）
2. 在高德地图里逐点搜名称，确认存在、地址正确、仍在营业
3. 写 `reason`（一句话）、修正 `stay_minutes`、填入 `tag_ids`
4. 填 `verified_by` 与 `verified_at`，`status` 从“待复核”改为“有效”
5. 未通过核验的置为“已关闭”，不参与召回
