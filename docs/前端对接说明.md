# 前端对接说明 · 漫步江城 CityWalk（后端已就绪）

> 给前端同学：后端接口已经跑通，你按这份改结果页即可。
> 接口契约以 `docs/api.md` 为准；本文是"怎么用"的说明 + 真实返回样例。

## 一、后端在哪、怎么起

| 项 | 值 |
|---|---|
| 本地地址 | `http://127.0.0.1:8000`（**不要用 localhost**，某些环境会解析到 IPv6 连不上） |
| 在线调试 | 浏览器打开 `http://127.0.0.1:8000/docs`，可直接点接口试 |
| 启动方式 | 双击 `backend\start_backend.bat`（自动建 venv + 装依赖 + 起服务） |
| 健康检查 | `GET /api/health`，返回 `"amap":"up"` 表示高德 Key 正常 |
| 本地跨域 | 仓库 Vue 的 vite 已配 `proxy /api → 127.0.0.1:8000`，本地无需 CORS |

## 二、必须改的 3 件事

| # | 现在（netlify 版） | 改成 | 为什么 |
|---|---|---|---|
| 1 | 直接调 `/api/deepseek/...`、`/api/amapgeo/...`（Netlify Functions） | 调 `POST /api/route/generate` | 点位和折线必须来自种子库 + 高德路径规划，不能是 LLM 编的 |
| 2 | 结果页只有 **1 条路线 + 故事 + 封面** | **3 个方案 Tab**：shortest / max / balanced，各自有折线、途经点、里程、时长、推荐理由 | "备选方案对比"是方案文档的核心功能，只有一条会少一个 FR |
| 3 | 6 个中文主题按钮（历史人文 / 建筑美学 …） | **8 个 tagId**，建议用 `GET /api/tags` 动态渲染 | 后端是 8 个固定 tagId；6 个中文主题里有 2 个重复映射、2 个没有入口 |

## 三、推荐页面流程

```
用户输入一句话（如"想走点安静的老街拍拍照"）
        ↓ POST /api/intent  {query}
    得到 tagIds: ["art","history","local","photo"]
        ↓ 用户选起点、终点（用 /api/tips 搜地名拿坐标，或地图点选）
        ↓ POST /api/route/generate {origin, destination, tagIds, effort}
    得到 3 条方案（每条含 polyline 折线 + waypoints 途经点）
        ↓ 渲染 3 个 Tab
用户点"换一批"或"这个点去过了"
        ↓ POST /api/route/replan {..., excludeIds: [已到过的 poiId]}
    重新给 3 条，且排除已到过的点
```

## 四、接口清单

| 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|
| POST | `/api/intent` | 一句话 → 标签 | 关键词匹配，不走 LLM |
| GET | `/api/tips?keywords=昙华林&city=武汉` | 地名 → 坐标（输入提示） | 用于起点/终点选择 |
| POST | `/api/route/generate` | 生成 3 条方案 | **核心接口** |
| POST | `/api/route/replan` | 换一批（排除已到过的点） | 多传 `excludeIds` |
| GET | `/api/route/{schemeId}` | 取单条方案 | 分享/回看 |
| GET | `/api/tags` | 8 个标签 | 渲染按钮 |
| GET | `/api/geo/regeo?lng=&lat=` | 坐标 → 地址 | 逆地理编码 |
| GET | `/api/health` | 健康检查 | 演示前自检 |
| POST | `/api/share` `{schemeId}` | 生成分享 token | 可选 |
| GET | `/api/share/{token}` | 读分享 | 可选 |

## 五、POST /api/intent

**请求**

```json
{ "query": "想走点安静的老街拍拍照" }
```

**响应**

```json
{ "tagIds": ["art", "history", "local", "photo"] }
```

说明：最多返回 4 个标签；返回空数组时前端可给一组默认标签（如 art + history + local）。

## 七、POST /api/route/generate（核心）

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `origin` | `{lng, lat}` | 是 | 起点坐标，GCJ-02 |
| `destination` | `{lng, lat}` | 是 | 终点坐标，GCJ-02 |
| `tagIds` | `string[]` | 是 | 1~4 个，见第九节标签表 |
| `tagOrder` | `string[]` | 否 | 兴趣优先级；不传 = 按 tagIds 顺序 |
| `effort` | `string` | 否 | `easy` / `normal` / `deep`（轻松 / 正常 / 深度），默认 `normal` |

### 响应字段（只列前端要用的）

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `success` |
| `schemes` | array | **3 条方案**，顺序：shortest / max / balanced |
| `schemes[].schemeId` | string | 方案 id，分享/回看用 |
| `schemes[].mode` | string | `shortest` / `max` / `balanced` |
| `schemes[].distanceM` | int | 全程米数（真实步行距离） |
| `schemes[].durationS` | int | 总秒数（走 + 逛） |
| `schemes[].walkS` | int | 纯走路秒数 |
| `schemes[].stayS` | int | 点位停留秒数 |
| `schemes[].waypointCount` | int | 途经点数量 |
| `schemes[].detourRatio` | float | 绕行倍数（1.0 = 直线，1.3 = 多走 30%） |
| `schemes[].difficulty` | string | 强度档位，直接显示字符串 |
| `schemes[].reason` | string | **推荐理由文案，直接显示** |
| `schemes[].polyline` | `number[][]` | 折线，每项 `[lng, lat]`，200~340 个点 |
| `schemes[].polylineSource` | string | `amap` = 真实路径 / `mixed` / `estimated` |
| `schemes[].waypoints` | array | 途经点，见下表 |
| `schemes[].crossing` | object | 过江提示 `{isCrossing, type, distanceM, extraMinutes}` |
| `validation` | object | 校验信息 `{passed, dropped, reasons}` |
| `routing` | object | 高德调用统计，页面不用显示 |

### `waypoints[]` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | int | 顺序号 |
| `poiId` | string | 种子库 id |
| `amapId` | string | 高德 POI 编号（可在高德地图搜到真实地点） |
| `name` | string | 名称 |
| `address` | string | 地址 |
| `lng` / `lat` | float | 坐标 |
| `typeName` | string | 类型（咖啡厅 / 历史建筑 …） |
| `tagIds` | string[] | 标签 |
| `stayMinutes` | int | 建议停留分钟 |
| `rating` | float / null | 评分 |
| `source` | string | `seed` / `amap` / `keyword` / `hot` |
| `distanceFromPrevM` | int | 距上一站的米数 |

### 耗时与缓存

- 第一次请求约 **2~3 秒**（要实时调高德步行接口）→ 按钮必须做 loading
- 同一对起终点第二次 **< 20 毫秒**（进程内缓存）
- 超过 30 秒没返回：先看后端有没有在跑（`/api/health`）

## 八、POST /api/route/replan（换一批）

在 generate 的请求体基础上多传一个字段：

```json
{
  "origin": { "lng": 114.3608, "lat": 30.5387 },
  "destination": { "lng": 114.3165, "lat": 30.5497 },
  "tagIds": ["art", "history"],
  "effort": "normal",
  "excludeIds": ["B0FFHOFC0V", "B001B1DIF0"]
}
```

响应结构与 generate 完全一致。前端把"已经展示过/已到过"的点位 `poiId` 攒起来传即可。

## 十、5 个注意事项（很容易踩）

1. **坐标顺序是 `[lng, lat]`（经度在前）**。高德 JS API 直接用；**Leaflet / Mapbox 要翻转成 `[lat, lng]`**，否则线会跑到别的地方。
2. **坐标是 GCJ-02（火星坐标）**。配高德底图没问题；换 OSM / Google 底图会偏几百米。
3. **折线点很多（200~340 个）**：只画一条 polyline + `waypoints` 里的点，不要给每个折线点都加 marker。
4. **`difficulty` 和 `reason` 直接显示字符串**，不要自己拼文案。
5. **错误格式统一如下**，前端按 `error.code` 分支处理：

```json
{ "error": { "code": "INVALID_DISTANCE", "message": "步行距离过长（约 18.2 公里），建议缩短起终点或改乘公共交通" } }
```

常见 code：

| code | 含义 |
|---|---|
| `SAME_POINT` | 起终点太近 |
| `INVALID_DISTANCE` | 步行距离过长（>15 公里） |
| `SCHEME_NOT_FOUND` | 方案不存在或已过期 |
| `ALL_KEYS_EXHAUSTED` | 高德 Key 全部不可用（临时故障） |

## 十一、验收清单（改完自己过一遍）

- [ ] 三个 Tab 都能画出折线，且线是**沿街道**的（不是两点连直线）
- [ ] 每个 Tab 的途经点名称 / 地址 / 评分显示正确
- [ ] 切换 Tab 不重新发请求（一次请求拿到 3 条）
- [ ] 点"换一批"，已经去过的点不再出现
- [ ] 一句话输入后，对应的标签按钮自动选中
- [ ] 后端没启动时，页面给出友好提示（不能白屏）
