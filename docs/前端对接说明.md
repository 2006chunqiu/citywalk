## 三、页面数据怎么流

```
用户输入起点 / 终点（可留空）
        ↓ GET /api/geo/geocode?address=武汉大学&city=武汉
   得到 lng / lat（GCJ-02）
        ↓
用户选主题 + 输入一句话（可只填其一）
        ↓ POST /api/intent { query }
   得到 tagIds（词表优先，最多 4 个）
   与主题标签合并 → 空则兜底 ["history","local"] → 截断 4 个
        ↓ POST /api/route/generate { origin, destination, tagIds, effort }
   得到 3 条方案，每条含 polyline（200~340 个点）+ waypoints
        ↓ src/lib/adapt.ts
   schemeToRoute（卡片字段）/ schemeToPath（折线坐标）
        ↓
   Leaflet 画折线 + 编号 marker + popup
        ↓
用户说「别给咖啡馆了 / 少走点路 / 换一批」
        ↓ parseRefine（不产生地点，只产生条件）
   excludeIds（当前方案里匹配到的 poiId）+ effort（easy / deep）
        ↓ POST /api/route/replan { origin, destination, tagIds, effort, excludeIds }
   重新映射 → 更新折线、marker、三条 Tab
```

对应文件：

| 文件 | 干什么 |
|---|---|
| `frontend/src/App.tsx` | 主流程：地理编码 → 意图 → 生成 → 映射 → 渲染 |
| `frontend/src/lib/api.ts` | 四个请求封装与类型：`geocodeAddress` / `postIntent` / `postGenerate` / `postReplan` |
| `frontend/src/lib/adapt.ts` | 后端 Scheme → 页面 Route / 折线；主题到标签的 `THEME_TAGS` |
| `frontend/src/components/MapView.tsx` | Leaflet 地图、瓦片、marker、popup |

## 五、generate 里前端实际用到的字段

| 字段 | 说明 |
|---|---|
| `schemes[].mode` | `shortest` / `max` / `balanced`，顺序固定 |
| `schemes[].title` | 路线短名，直接显示；不要用 mode 拼「最短路线」 |
| `schemes[].distanceM` / `durationS` | 真实步行距离 / 总时长（走 + 逛） |
| `schemes[].waypointCount` | 途经点数量 |
| `schemes[].reason` | 推荐理由，直接显示，不要自己拼 |
| `schemes[].polyline` | `[[lng, lat], ...]`，**经度在前** |
| `schemes[].polylineSource` | `amap` 真实路径 / `mixed` 部分降级 / `estimated` 全直线 |
| `schemes[].waypoints[]` | `name` / `address` / `lng` / `lat` / `typeName` / `stayMinutes` / `rating` / `poiId` |
| `routing` | 高德调用统计，页面不显示，排障用 |

耗时：首次 2~3 秒（实时走高德），同起终点第二次很快（进程内缓存）。按钮要有 loading。

### 「再改一下」的规则

- 输入只翻成两类参数：`excludeIds`（排除哪些 poiId）和 `effort`（easy / deep），不会生成新地点。
- 排除：按点位名称 / `tagIds` 匹配当前三条方案，命中即加入排除列表；多次修改会累积。
- 换一批：只排除当前选中方案的点，避免一次把走廊候选池掏空。
- 少走 / 多逛：`effort=easy/deep`，并在重排后自动选「最短路线」/「站点最多」的那条。
- 后端会丢弃剔除后 0 途经点的方案；三条都空时返回 `400 NO_POIS_LEFT`，前端保留原路线并提示。
- 词表覆盖：咖啡、公园、历史、美食、文艺、江景、市场、拍照、亲子、少走、多逛、换一批；更自由的说法会提示「没太听懂」。

### 分享按钮

- 路线详情底部「分享」：`POST /api/share`（只传 `schemeId`）→ 拿 `{ url, text }`。
- 复制内容 = `text` + 换行 + `window.location.origin + url`，即「分享语 + 可打开的 `/s/{token}` 页面」。
- `text` 有 AI 版和模板版：配了 `LLM_API_KEY` 让模型写，失败/未配置退回「我走了条 X 公里的「title」，从 A 到 B，一共 N 站。」
- 手机通过局域网 HTTP 打开时 `navigator.clipboard` 可能被浏览器限制，代码里用 `execCommand("copy")` 兜底；再失败才弹 `prompt` 让用户手动复制。
- `/s/{token}` 是后端直接返回的 HTML 分享页：标题、公里数、预计分钟、站点列表、每站高德导航；不依赖前端进程。

## 八、容易踩的坑

1. **地址用 `127.0.0.1`，不要用 `localhost`**：本机可能解析到 IPv6，后端连不上。
2. **高德 Key 必须是「Web服务」平台**：`Web端(JS API)` 的 Key 调 `/v3/...` 会报 `USERKEY_PLAT_NOMATCH`。
3. **个人 Key 约 3 QPS**：逐段调步行规划会触发 `10021 CUQPS_HAS_EXCEEDED_THE_LIMIT`；后端已做 `0.35s` 节流 + 退避重试，不要在前端并发狂点「生成」。
4. **坐标顺序**：接口是 `[lng, lat]`（经度在前）；Leaflet 要的是 `[lat, lng]`，`adapt.ts` 里已经翻好。
5. **GCJ-02 + 高德瓦片**：底图用 `webrd0{1-4}.is.autonavi.com/appmaptile?...style=8`；换 OSM/CartoDB 会偏几百米，而且本机网络访问不到这两家瓦片。
6. **地理编码会模糊匹配**：乱写中文可能被高德匹配到某个村，后端已加字符重合校验；纯符号/英文乱写返回 404。前端只要把 `GEOCODE_NOT_FOUND` 的 message 显示出来即可。
7. **参数错误是统一结构**：`422` 也会返回 `{"error":{"code":"INVALID_REQUEST","message":"..."}}`，不会出现 FastAPI 默认的 `detail` 数组。
8. **Windows 起 dev server**：`Start-Process npm` 会失败（npm 是 `.ps1`）；要么直接开终端 `npm run dev`，要么用 `node node_modules/vite/bin/vite.js --port 5173`。
9. **分享代理必须写 `^/s/`，不能写 `/s`**：Vite 的代理 key 是前缀匹配，`/s` 会把 `/src/main.tsx` 也转发给后端，页面直接白屏 404。
10. **手机真机**：后端要 `--host 0.0.0.0`；Vite 已 `host: true`；手机和电脑同一 Wi‑Fi，用电脑局域网 IP（当前 `10.76.157.89`）访问 `http://10.76.157.89:5173`。公司/校园网若开 AP 隔离，手机可能连不上。
