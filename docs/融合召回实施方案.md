# 融合召回实施方案（双通道）

> 给后端同学：本文说明如何把"高德召回"与"种子库召回"两条线接起来，并在选取阶段做配额，
> 保证每条路线既有大景点、也有小店。
> 契约仍以 `docs/api.md` 为准，本文只讨论实现。

---

## 一、要解决什么问题

产品目标是：**一条路线里，既有黄鹤楼、东湖这种人人都知道的大点位，也有巷子里的独立书店、咖啡馆这种高德不会推荐的小点位。**

现在只有种子库一条线。244 条种子库里虽然已经混装了一些大景点，但：

- 覆盖不全会漏（用户起点附近的大景点没被收录就永远不出现）
- 新开的大点位无法自动发现
- 反过来，小店依赖人工维护，规模上不去

所以需要两条线：**高德负责广度（大点位），种子库负责深度（小点位与主观标签）**。

---

## 二、现状核对（改之前先确认）

| 通道 | 位置 | 状态 |
|---|---|---|
| 种子库召回 | `services/recall.py: recall()` | 在用 |
| 高德周边检索 | `services/amap.py: place_around()` | **函数已写好，全项目无调用点** |
| 沿走廊撒点 | `services/recall.py: corridor_centers()` | **定义了但从未被使用** |
| DeepSeek | `services/llm.py` | 只做意图识别与文案，不参与选点 |

也就是说：**高德这一路的零件都齐了，只差接线。** 本次改动主要是接线 + 合并 + 配额。

---

## 三、总体流程

```
起点/终点/标签
      │
      ├─► 通道 B：种子库召回  recall()            → 小点位池（source=seed）
      │
      └─► 通道 A：高德周边召回 recall_amap()      → 大点位池（source=amap）
              沿 corridor_centers 取 3 个中心点
              每个中心点用标签对应的 typecodes 查 2 页
      │
      ▼
   合并去重（按 amapId，种子库优先保留）
      │
      ▼
   打分排序（algo/scoring.py，不改公式）
      │
      ▼
   配额选取（新增）→ 保证 seed 与 amap 各有下限
      │
      ▼
   分段路径规划（services/routing.py，不改）
```

## 四、通道 A：高德召回

### 4.1 函数签名

新增到 `services/recall.py`：

```python
async def recall_amap(
    origin: tuple[float, float],
    destination: tuple[float, float],
    tag_ids: list[str] | tuple[str, ...],
    *,
    parts: int = 3,          # 走廊中心点个数
    page_size: int = 25,
    max_pages: int = 2,      # 每个中心点最多翻 2 页
    dedupe_ids: set[str] | None = None,   # 种子库已有的 amapId，避免重复
) -> list[Poi]:
```

返回 `list[Poi]`，其中 `source="amap"`，`poi_id` 直接用高德 POI ID（与种子库主键规则保持一致）。

### 4.2 中心点策略

复用已有的 `corridor_centers(origin, destination, parts=3)`：

- `parts=3` → 走廊上 3 个等分中点
- **不要**以起点为圆心画一个大圆，那样会捞到一堆要绕远路的点

### 4.3 types 参数

从 `services/tags_data.py` 取标签的 `typecodes`，多个用 `|` 拼接后传给 `place_around` 的 `types`：

```python
codes = sorted({c for t in tag_ids for c in TAG_INDEX[t]["typecodes"]})
types = "|".join(codes)
```

一次调用覆盖全部已选标签，**不要按标签逐个查**（否则调用量随标签数线性增长，会突破预算）。

### 4.4 半径

复用 `scoring.buffer_radius_m(straight)`，与种子库通道**用同一个半径**，避免两套范围不一致导致结果不可解释。

### 4.5 调用预算

| 项 | 上限 |
|---|---|
| 中心点 | 3 |
| 每点页数 | 2 |
| **高德召回调用** | **≤6 次/次生成** |

超出预算直接停止翻页，不要重试。

### 4.6 异常处理

`place_around` 抛 `AllKeysExhausted` 或 `AmapError` 时：

- 打日志 `recall_amap_failed`，**返回空列表**，不中断整次生成
- 后续配额逻辑自动降级为纯种子库（见 6.3）

## 五、通道 B：种子库

只加一件事：返回的 `Poi` 里 `source` 保持 `"seed"`（若现有数据里 source 字段为空，读取时兜底为 `"seed"`）。

## 六、合并与配额

### 6.1 合并去重

```python
merged = []
seen = set()
for poi in seed_pois + amap_pois:      # 种子库优先，保证人工标注不被覆盖
    key = poi.poi_id
    if key in seen:
        continue
    seen.add(key)
    merged.append(poi)
```

要点：

- **种子库在前**，同一个点位两边都有时保留种子库那条（它带有人工标签、入选理由、停留时长）
- 去重键用 `poi_id`，前提是两边都用高德 POI ID
- 名字相同的不同点位不要合并（连锁店是真实存在的）

### 6.2 配额选取（本次改动的核心）

**不能只靠打分排序。** 原因：

```
H（热度）= rating / 5
黄鹤楼     4.7 → 0.94
独立咖啡店 无评分 → 0.50（中值默认）
```

大景点的平台评分天然高，小店没有评分，**纯加权必然被大景点挤掉**，融合就失效了。

所以在 `algo/scoring.py` 的 `select_waypoints()` 增加可选参数：

```python
def select_waypoints(
    ranked,
    target_n: int,
    min_gap_m: float = 200.0,
    max_same_type: int = 2,
    quota: dict[str, int] | None = None,   # {"seed": 2, "amap": 1}
) -> list[Poi]:
```

推荐配比（按途经点数量）：

| 途经点数量 | seed 下限 | amap 下限 |
|---|---|---|
| 3 | 1 | 1 |
| 4 | 2 | 1 |
| 5 | 2 | 1 |
| 6 | 3 | 2 |

### 6.3 选取算法（伪代码）

```python
def select_with_quota(ranked, target_n, quota, min_gap_m, max_same_type):
    chosen, type_count = [], {}
    need = dict(quota)                     # 剩余配额

    # 第一轮：按分数顺序填充，同时满足配额
    for poi, score, detail in ranked:
        if len(chosen) >= target_n:
            break
        if not _passes(poi, chosen, type_count, min_gap_m, max_same_type):
            continue
        # 若某来源配额已满，但还有其它来源没填够，跳过它
        src = poi.source
        others_unmet = any(v > 0 for k, v in need.items() if k != src)
        if need.get(src, 0) <= 0 and others_unmet:
            continue
        chosen.append(poi)
        need[src] = need.get(src, 0) - 1
        type_count[poi.typecode] = type_count.get(poi.typecode, 0) + 1

    # 第二轮：配额没填够就放宽（按分数补齐，忽略配额）
    if len(chosen) < target_n:
        for poi, score, detail in ranked:
            if len(chosen) >= target_n:
                break
            if poi in chosen:
                continue
            if not _passes(...):
                continue
            chosen.append(poi)

    return chosen
```

**降级原则**：配额填不满时，宁可少一个点，也不要塞不相关的点。若某一通道整体为空（例如高德挂了），配额约束自动失效，退回纯种子库逻辑。

### 6.4 日志

每次生成必须输出一行可核对的统计：

```
recall: seed=38 amap=22 merged=54 | quota need={seed:2,amap:1} got={seed:3,amap:1} | amapCalls=6
```

这行日志是验收第 4 条的依据。

## 七、DeepSeek 的边界（硬约束）

模型**不允许**产出点位名称、坐标、距离。只允许三处：

| 用途 | 输入 | 输出 | 落地方式 |
|---|---|---|---|
| 意图识别 | 用户一句话 | `tagIds` | 已有 `services/intent.py`，词表命中不足 2 个时才调模型 |
| 关键词扩展 | 一句话 | `["老街","里份","旧居"]` | 用于通道 A 的 `keywords`，**不直接落地为点位** |
| 文案生成 | 已选定点位 | 路线叙事、分享文案 | 已有 `llm.py: polish_schemes` / `share_text` |

审查标准：**把 `llm.py` 里的所有返回值通读一遍，如果任何一处能影响"去哪个点"，就是违约。**

## 八、接口变化（向后兼容）

`POST /api/route/generate` 响应中，`schemes[].waypoints[].source` 的取值集合从 `seed` 扩展为：

| 值 | 含义 |
|---|---|
| `seed` | 种子库（小点位主力） |
| `amap` | 高德周边检索（大点位主力） |
| `keyword` | 关键词补充召回 |
| `hot` | 热度兜底 |

**已有字段不改名、不改类型**，前端不需要改动。新增一个统计字段：

```json
"recall": {
  "seedCount": 38,
  "amapCount": 22,
  "merged": 54,
  "amapCalls": 6,
  "widened": false
}
```

## 九、配置项

加到 `app/config.py`，全部可关闭（便于答辩时对比"单通道 vs 双通道"）：

```python
recall_amap_enabled: bool = os.getenv("RECALL_AMAP", "1") != "0"
recall_amap_parts: int = int(os.getenv("RECALL_AMAP_PARTS", "3"))
recall_amap_max_pages: int = int(os.getenv("RECALL_AMAP_MAX_PAGES", "2"))
seed_min_ratio: float = float(os.getenv("SEED_MIN_RATIO", "0.4"))
```

`RECALL_AMAP=0` 时完全退回单通道，用于对照演示。

## 十一、工作量与顺序

| 步骤 | 内容 | 工时 |

| 1 | `recall_amap()` 接线（含 types 拼接、去重、降级） | 半天 |

## 十二、风险

| 风险 | 应对 |
|---|---|
| 高德召回把预算打满，导致路径规划没额度 | `recall_amap` 调用上限锁死 6 次，且优先级低于 `routing` |
| 大点位仍然挤掉小店 | 配额是第一道闸；若仍不达标，把 `SEED_MIN_RATIO` 调到 0.5 |
| 两边点位重复导致去重后数量不足 | 去重键严格用高德 POI ID；种子库录入时必须填 `amapId` |
| 答辩时被问"高德推荐和种子库怎么融合" | 用日志那行数字回答，比口头描述可信 |
